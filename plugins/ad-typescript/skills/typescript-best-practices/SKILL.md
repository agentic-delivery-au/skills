# TypeScript best practices

Apply the **ad-general:principle-type-system-discipline** principle skill first; this skill grounds
it in TypeScript syntax.

The `typescript-lsp` language server and the ESLint hook that `ad-typescript` ships report type
errors and lint findings after each edit. That is early feedback: pre-commit and CI remain the gate.
A quiet hook is not a passing gate, because the hook checks only the edited file, never runs `tsc`,
and reports formatting only where the ESLint config runs Prettier, as the
[baseline](references/baseline.md)'s does. Run the project's own lint and type-check gate and do not
re-derive by eye what it checks. Its evidence is each command's output: exit status 0 and no
reported problem. What follows is the judgement it does not check.

| Rule                  | Summary                                                                                                                                                                                                                                                                                                                                                                  |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Discriminated unions  | Model variants with a `kind` literal discriminant so impossible states can't be represented. No optional-field bags.                                                                                                                                                                                                                                                     |
| Branded types         | Brand primitives with `& { readonly __brand: "X" }` so they can't be mixed up. Validate once at creation.                                                                                                                                                                                                                                                                |
| Constructive modeling | Build the shape so the illegal value can't be constructed. `[T, ...T[]]` for non-empty, `[T, T][]` for even length, `start` plus `duration` for a range. Not a runtime guard, not a wish for refinement types.                                                                                                                                                           |
| Simplest total type   | Keep `T[]` while every operation on it stays total. Strengthen to `NonEmpty<T>` only where the loose type forces `!`, a cast, or a "should never happen" throw.                                                                                                                                                                                                          |
| Return types          | An exported function's return type is the type it promises, not the widest thing it happens to return. Give an anonymous inline return shape a name.                                                                                                                                                                                                                     |
| `unknown` over `any`  | External data is `unknown`, including what a library types as `any` (`JSON.parse`, `Response.json()`). `no-explicit-any` reports an `any` you write, not one handed to you, and the [baseline](references/baseline.md) has no `no-unsafe-*` rules to report one. `any` disables type checking everywhere it touches.                                                     |
| Earned suppressions   | An `eslint-disable` covers one line, never a file. A file-level disable that names a rule and gives a reason passes the [baseline](references/baseline.md)'s suppression rules, and hides every future violation of that rule, not just today's. The reason must be true of that line: no tool checks it.                                                                |
| No `as` casts         | Every `as` is a runtime crash waiting. Cast only after validation. The sanctioned exceptions are listed in `references/patterns.md`; that list is closed and does not generalise.                                                                                                                                                                                        |
| Narrowing hierarchy   | Discriminant switch > `in` operator > `typeof`/`instanceof` > user-defined type guard > `as`.                                                                                                                                                                                                                                                                            |
| Type guards           | Must verify the claim. A lying guard is worse than `as` because the bug hides behind a name that says it's safe. Name them `isX` or `hasX`.                                                                                                                                                                                                                              |
| Exhaustiveness        | Inline `const _exhaustive: never = x;` in default arms so the compiler errors when a new variant is added.                                                                                                                                                                                                                                                               |
| `satisfies` over `as` | Validates the value without widening literal types.                                                                                                                                                                                                                                                                                                                      |
| Boundary validation   | Parse where data crosses in, into a named domain type. `Record<string, unknown>` (however spelled) stops at that parse. Trust types inside. See the **ad-general:principle-boundary-discipline** principle skill.                                                                                                                                                        |
| Schema-derived types  | Reach for `Pick`/`Omit`/`Parameters`/`ReturnType`/`Awaited`/`typeof` before declaring a new interface.                                                                                                                                                                                                                                                                   |
| Object args           | Pass objects, not positional, so argument order is self-documenting. Skip on hot paths (per-frame render, tokenizers, parsers).                                                                                                                                                                                                                                          |
| Real tests            | Don't mock what you can run. Mock only what you can't: the network, the clock, a paid API. A test that mostly asserts on its own mocks proves the mocks. Prove a new test can fail before trusting it. Query clients by role and label, not test id.                                                                                                                     |
| Structured telemetry  | Prefer structured logger diagnostics with enough context to debug from an id. Where there is no logger, `console.error`/`warn` are the fallback; where `no-console` reports them, as the [baseline](references/baseline.md)'s does, each carries `eslint-disable-next-line no-console` with a reason. Never log a request body or a token. See `references/patterns.md`. |

Examples: `references/patterns.md`. The ESLint and TypeScript configuration these rows assume:
`references/baseline.md`.
